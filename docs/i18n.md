# i18n (plugin and CLI)

> Status: `authoritative`. The user-visible copy of the plugin and `courier-cli` follows the rules described in this document.

## Language rules

| Side            | Default language                 | Basis                                                                                         | Override                                                                            |
| --------------- | -------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Obsidian plugin | Follows the Obsidian UI language | `obsidian`'s `getLanguage()`; when empty, `navigator.language`; if still unavailable, English | No in-plugin switch; restart / reload the plugin after changing Obsidian's language |
| `courier-cli`   | Follows the OS language          | `LC_ALL` > `LC_MESSAGES` > `LANG` > `Intl.DateTimeFormat().resolvedOptions().locale`          | `--lang <zh\|en>` > `COURIER_LANG` > system language                                |

- Only Chinese and English. Every `zh*` (`zh`, `zh-CN`, `zh-TW`, `zh-Hans`, `zh_CN.UTF-8`) uses **Simplified Chinese**; every other language, `C`, `POSIX`, empty and unrecognized values use English.
- The `getLanguage()` the plugin uses is `@since 1.8.7` in Obsidian, which matches `minAppVersion` in the current `manifest.json`; no version bump is needed.
- The CLI's `--lang` may go before or after a subcommand (`main.ts` strips it before commander parses), accepts `--lang en` and `--lang=en`, and the last one wins when repeated. An invalid or missing explicit value exits with an error instead of falling back silently; the error message uses the system language (English when that cannot be recognized).
- The CLI does not persist the language choice. A daemon pins the language with `COURIER_LANG=en` (for example systemd's `Environment=`).
- The CLI's `--json` is a machine interface: field names, `fileTypes` ids, paths and the like do not change with the language.

## Catalogs and runtime

```
packages/plugin/src/i18n/
  index.ts     # Locale, setLocale/getLocale, t, plural, messagesFor
  zh.ts        # Chinese catalog, the source of truth for keys
  en.ts        # English catalog, Record<keyof typeof zh, string>
  locale.ts    # resolveObsidianLocale

packages/cli/src/i18n/
  index.ts     # same as above, module default is en
  zh.ts
  en.ts
  locale.ts    # localeFromTag / detectSystemLanguage / resolveCliLocale
```

- `zh.ts` is a plain object with flat keys (`common.cancel`, `dialog.recycleBin.title`, `cli.status.label.server`); the type of `en.ts` is `Record<MessageKey, string>`, so a missing or an extra key fails at the `tsc` stage.
- `t(key, params?)` replaces `{name}` placeholders with a single `replace`; the inserted values are not scanned a second time, and things such as `$&` are taken literally. A missing parameter leaves a visible `{name}`, which the tests catch.
- English plurals use a key pair plus `plural(oneKey, otherKey, count)` (for example `history.relative.minutes.one/.other`); the Chinese pair writes the same text for both keys.
- No dependency such as i18next and no new shared package: the two sides differ in default language, lifecycle and message set, so copying roughly 40 lines of runtime is lighter.
- **Never pre-evaluate localized copy in a module-level constant.** The language is decided only in `onload` / at CLI startup, but files other than `zh.ts`/`en.ts` execute when the bundle loads; storing the result of `t(...)` in a module-level `const` freezes it to the default language. Tables that need localization (file types, settings groups, sync actions, conflict actions and so on) must always be written as functions or call `t(...)` at render time.

## What is not translated

- `console.log` / `console.error` diagnostics, the host log tags of `@courier/engine` (such as `push x failed`), and the validation details the server returns.
- Machine identifiers: paths, `ck_` keys, vault ids and version strings.
- The `description` in Obsidian's `manifest.json` (Obsidian supports only one description).
- Paths, file type ids, settings group ids, `ck_` keys, units such as `KB/MB/GB`.
- The machine fields of `status --json`.

## Copy conventions

- Chinese follows Obsidian's terminology: `Vault` → `远程库`, `Vault 密码` → `库密码`, `远端版本` → `远程版本`, `对端` → `其他设备`. Chinese uses full-width punctuation (`：`, `，`, `。`, `「」`, `…`).
- English uses sentence case, buttons take no trailing period, paths are in double quotes; plurals must be correct (`1 file` / `2 files`, `0 files`).
- Error copy states "what happened + what to do next" and must not use implementation terms such as 「派生」 (derive) or 「服务端宿主」 (server host).
- The catalog owns the whole sentence; do not assemble half a sentence at the call site; use placeholders when a variable is needed.

## Adding copy / a language

1. Add the key and the Chinese text in `zh.ts`.
2. Add the same key in `en.ts` (TypeScript enforces it).
3. Use `t("...")` or `plural(...)` at the call site; do not cache the result at module level.
4. Run that side's tests; `i18n.test.ts` checks key alignment, empty values, whether Chinese remains in the English catalog, whether identical values are on the allowlist, and whether any template still has a placeholder.
5. Adding a third language: add `<locale>.ts` on both sides (typed `Record<MessageKey, string>`), extend `Locale` and the catalog map, and add language-resolution tests. The plugin must also map the language in `resolveObsidianLocale`; the CLI must map it in `localeFromTag` and confirm the OS detection path.

## Tests

- **Language-resolution unit tests**: the plugin's `zh*` / others; the CLI's `LC_ALL`/`LANG`/`Intl` combinations, flag/env precedence, `--lang` after a subcommand, missing and invalid values.
- **Catalog completeness**: one `i18n.test.ts` on each side, covering key alignment, no Han characters in English, the allowlist of identical values, and no leftover placeholders when rendering Proxy parameters.
- **Plugin e2e**: `setStubLanguage("en")` in `obsidian-stub.ts` makes the real plugin class render with the English catalog; `resetStubState()` resets it to Chinese.
- **Real Obsidian**: `sync.obsidian.test.ts` reads the running Obsidian's `document.documentElement.lang` through `syncPluginLocale`, then generates the expected copy from the plugin catalog; so it runs under both Chinese and English UIs.
- **CLI**: `status.test.ts` covers the Chinese and English status lines and column alignment; `program.test.ts` covers the help copy in both languages; the daemon e2e calls `runDaemon` directly with English explicitly (in production `main.ts` decides from the system language).
